### Параметры запуска

`start-<ключ>.cmd` запускает `llama-server` на `127.0.0.1:8080` с:

- KV-кэшем `q8_0` (вдвое меньше VRAM; для моделей с размером головы внимания, кратным 32);
- `--reasoning off` для ролей, где «размышления» только замедляют ответ;
- сэмплингом из рекомендаций авторов моделей (`E:\AI\Scripts\models\catalog.ps1`);
- `--fit on` (по умолчанию): не влезшие слои уходят на CPU;
- `--fit-target 256` (параметр `-FitTarget`): стандартные 1024 МиБ запаса выталкивали слои 4B-модели
  на CPU — 26 ток/с вместо 42.

### Что проверить отдельно — ответы

- Ответ по JSON-схеме через `/v1/chat/completions` на настоящих моделях работает: 52/52 у
  всех, обрывов по `max_tokens` нет (кроме рассуждающих моделей без бюджета).
- Ход 7 империй на 4 слотах: 19–25 с у быстрых 4B-моделей, 38 с у Qwen3.5 на прогретой карте —
  в типичный ход игрока (30–60 с) укладывается.
- Модель занимает ~3,2 ГБ из 4 при `--fit-target 256`; под долгой нагрузкой карта держится у
  88–90 °C и сбрасывает частоту (раздел 3.10 бенчмарка).

## Бюджет на ход (оценка, проверить бенчмарком)

Ответ стратега ≈ 150–250 токенов, сводка ≈ 1–2 тыс. токенов. При 7 AI-империях и ответе за
5–10 с последовательная обработка занимает 35–70 с — на грани типичного хода игрока. Отсюда:

- на «лёгкой» и «средней» сложности опрос раз в 3–5 ходов покрывает всех с запасом;
- на «сложной» нужны параллельные слоты (`-np`), короткие сводки и приоритет триггерных
  запросов;
- кэш общей части промпта (`--cache-reuse`) сокращает обработку сводки.
