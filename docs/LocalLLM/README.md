## 1. Зачем

Опытный игрок MOO2 уже на первом ходу знает весь план партии: AI ведёт себя по одним и тем же
правилам, и через пару лет игры их выучиваешь наизусть. Случайность вносят только Антаране и
расположение планет.

Цель — сделать AI-империи **менее предсказуемыми и более «живыми»**, не ломая правил игры:

- стратегия, которая меняется в ответ на то, что происходит именно в этой партии;
- дипломатия и шпионаж с памятью и мотивами, как в Stellaris;
- флот, который адаптируется к тому, что AI реально увидел у противника;
- больше событий и текста — сообщения лидеров, новости GNN, хроника.

Локальная LLM (llama.cpp, OpenAI-совместимый `llama-server` на `localhost`) выступает
**советником и рассказчиком**. Движок по-прежнему считает всю математику и бросает все кубики.

### 1.1 Позиционирование: не «Stellaris на минималках»

> **MOO2, в которой соперники помнят, приспосабливаются и плетут интриги.**

Механики Stellaris и других игр — средство, а не цель. Сильные стороны MOO2, которые нельзя
потерять: пошаговая партия на вечер-два, тактические бои, где проект корабля решает исход,
4–8 соперников, каждого из которых знаешь в лицо, понятные цифры. Отличие проекта — не
количество механик, а **живые соперники**: память и характер, честная разведка и
перестройка флота под увиденное, шпионаж со встречными рисками, тексты под конкретную партию.

**Фильтр для каждой новой механики:**

1. Делает ли она соперников живее или укрепляет ядро MOO2 (проекты кораблей, тактика,
   компактная партия)?
2. Помещается ли она в интерфейс MOO2 без новых больших экранов управления?
3. Заметна ли она в партии на 3–6 часов, а не только к 300-му ходу?

Механика, не прошедшая фильтр, откладывается. Результат фильтра по механикам —
[mechanics.md](mechanics.md), раздел 1.4. Все новые механики — отдельным набором правил:
кто хочет чистую 1.50, играет без него.

## 2. Почему MOO2 предсказуем — в терминах кода

| Наблюдение | Где в коде |
|---|---|
| Характер AI задаётся один раз при старте по таблице «раса × сложность» | `ken.cpp:134` (`personality`), `ken.cpp:333` (`objectives`) |
| Цель империи (`objectives`) — одна из 6 и дальше не меняется | `orion2_consts.h:472-480`, поле `s_player::objectives` (`orion2.h:1604`) |
| AI проектирует корабли **против игрока 0** (человека) и знает его технологии без разведки | `aidesign.cpp:196-215` (щит цели), выбор набора защиты через `Best_Weapons_Are_Beams(&world->players[0])` в `Auto_Design_Ship` (`aidesign.cpp:1376`) |
| События — фиксированная таблица из 36 типов, выбор по вероятности и задержке | `events.cpp:773` (`Determine_Event`), `orion2_consts.h:166`, `static_assert` в `orion2_consts.h:1445` |
| Дипломатия — таблицы характеров и пороги | `diplomac.cpp:811` (`Get_Player_Diplomacy_Personality`), `diplomac.cpp:3468` (`Diplomacy_Test`) |
| Шпионы распределяются взвешенным случайным выбором по формуле | `spy.cpp:48` (`Allocate_AI_Spies`), выбор в `spy.cpp:223` |

Вывод: у AI мало «ручек», и почти все они выставляются один раз за партию или считаются
по фиксированной формуле. Именно эти ручки — естественные места для подсказок LLM.

## 3. Принципы

1. **Движок считает, LLM выбирает.** Модель не решает арифметику и не двигает корабли. Она
   получает сводку, которую подготовил движок, и выбирает вариант из закрытого меню.
2. **Кубики остаются у движка.** LLM — плохой генератор случайности: модели сваливаются в
   «любимые» ответы. Случайность берётся из игрового RNG (`random.cpp:25`), который сохраняется
   в сейв. LLM даёт другое — **разнообразие, зависящее от контекста** (характер лидера, история
   обид, увиденное).
3. **Закрытое меню и JSON-схема.** Ответ ограничен JSON-схемой (`response_format`), llama.cpp
   превращает её в грамматику, и модель физически не может выйти за пределы допустимых
   вариантов. В каждом меню есть вариант «ничего не менять».
4. **Честная информация.** AI получает только то, что его империя видела: увиденные в бою
   корабли, данные шпионов, контакты. Это одновременно убирает «читерство» AI и даёт
   шпионажу и разведке реальную цену.
5. **Асинхронность и запасной вариант.** Ход никогда не ждёт LLM. Нет ответа вовремя — AI
   играет по исходным правилам.
6. **Ответ LLM — это записанный ввод.** Директивы сохраняются в сейв, повтор игры
   воспроизводит их без повторного вызова модели. В мультиплеере модель вызывает только хост.
7. **Выключено по умолчанию.** Всё за флагом в конфиге: без него игра ведёт себя побайтно
   как upstream (это проверяет turn oracle, `turn_oracle.cpp`).
8. **Только локально.** Никаких внешних API: игровое состояние не уходит с компьютера.

## 4. Архитектура

### 4.1 Компоненты

```
┌──────────────── orion2re (игровой рабочий поток) ─────────────────┐
│                                                                   │
│  NEXTTURN::Next_Turn_Calc (nextturn.cpp)                          │
│    ├─ AIDATA::Compute_AI_Data ──────────► [llm::Apply_Directives] │◄─┐
│    ├─ NPC_Diplomacy / AIBUILD / AIMOVE / aitech / spy ...         │  │ директивы
│    │      (читают директивы как веса/смещения)                    │  │ хода N+1
│    └─ конец хода ───────────────────────► [llm::Queue_Requests]   │  │
│                                                │ сводки            │  │
│  Триггеры (колония потеряна, бой, техно...) ──┘                   │  │
└───────────────────────────────────────────────│───────────────────┘  │
                                                 ▼                      │
                         ┌──────── llm-поток (SDL_CreateThread) ────────┐
                         │ очередь запросов → HTTP POST (libuv TCP)     │
                         │ ← JSON (yyjson) → проверка → хранилище       │
                         └───────────────────────│──────────────────────┘
                                                 ▼
                              llama-server (отдельный процесс, localhost)
```

| Компонент | Где | Что делает |
|---|---|---|
| `llm::s_config` | новый раздел конфига (`specs/config/main.json5`) | вкл/выкл, адрес сервера, частота, бюджет, таймауты |
| Сборщик сводок | `src/game/llm/` (новое) | из `game::s_view` и `AIDATA::s_state` строит компактный текст |
| Очередь и поток | `src/game/llm/` | `SDL_CreateThread` (так же делают `platform.cpp:1692`, `netadapter.cpp:358`) |
| HTTP-клиент | `src/game/llm/` | минимальный HTTP/1.1 поверх libuv (уже есть: `router_client.cpp:408`) |
| JSON | — | yyjson уже подключён (`config/mod_manifest.cpp`) |
| Хранилище директив | `src/game/llm/` | по империям, с номером хода выдачи и сроком действия |
| Применение | вызов после `Compute_AI_Data` (`nextturn.cpp:36`) | переносит директивы в поля и веса, которые читают модули AI |
| Секция сейва | новый тип необязательной секции | директивы, память разведки, память обид |

Новых зависимостей не требуется: libuv, yyjson и SDL-потоки уже в проекте.

### 4.2 Время: как спрятать задержку

```
ход N:   движок считает ход → в конце собирает сводки → ставит запросы в очередь
         ↓
         игрок думает над своим ходом (обычно десятки секунд)
         ↓  ← в это время llm-поток получает ответы
ход N+1: Apply_Directives применяет всё, что успело прийти
         не пришло → AI играет по исходным правилам, запрос остаётся в очереди
```

Ход игрока — бесплатное окно для вычислений. Задержка видна только там, где игрок ждёт
синхронно: в окне дипломатии и в начале боя. Туда LLM напрямую не ставим, а готовим всё заранее.

### 4.3 Вход: сводка состояния

Уроки чужих проектов (раздел 11): большие таблицы сбивают модели, растущая история раздувает
контекст. Поэтому:

- **короткий текст**, а не дамп структуры: 30–60 строк, ~1–2 тыс. токенов;
- **только видимое** этой империи (контакты, разведка, свои данные);
- **собирается заново** на каждый запрос, без накопления истории;
- **готовые оценки от движка** — соотношение сил, отставание в технологиях, угрозы
  (`AIDATA::s_player_assessment`, `aidata_state.h:370`), чтобы модели не нужно было считать;
- **короткая память**: последние 3–5 своих решений и список «обид» (кто напал, кто нарушил
  договор) — ограниченный по размеру.

Пример сводки и схемы ответа есть в тесте `E:\AI\Scripts\models\test-server.ps1`.

### 4.4 Выход: директива

Пример схемы стратегической директивы (упрощённо):

```json
{
  "objective":   "militarist | expansionist | technologist | industrialist | ecologist | diplomatic | keep",
  "war_stance":  "seek_peace | hold | escalate",
  "rival":       "<id игрока или none>",
  "diplomacy":   [{ "empire": "<id>", "action": "propose_peace | propose_trade | threaten | ... | none" }],
  "spy_target":  "<id игрока или none>",
  "spy_mission": "steal_tech | sabotage | hide",
  "fleet_doctrine": "anti_missile | anti_beam | anti_boarding | balanced | keep",
  "reasoning":   "до 300 символов, для лога и отладки"
}
```

> Бенчмарк 20.11.2026: список `diplomacy` модели заполняют шумом, а `escalate` во время войны
> читают как «драться сильнее». Предложение — схема v2: отношение к каждой империи и
> однозначная военная позиция ([benchmark](RTX_3050_ti/benchmark-2026-11-20.md), раздел 3.1).

Движок дополнительно проверяет ответ: перечисления совпадают с реальными игроками, директива
не нарушает правил (нельзя объявить войну тому, с кем нет контакта), числовые смещения
обрезаются по границам из конфига.

### 4.5 Детерминизм, сейвы, мультиплеер

- **RNG.** Код LLM никогда не тянет числа из общего RNG (`random.cpp:25`) — иначе
  поменяется поток случайных чисел и ломается воспроизводимость.
- **Сейв.** Директивы, память разведки и обиды хранятся в новой **необязательной** секции
  сейва. Неизвестные необязательные секции при загрузке пропускаются (ошибка возникает только
  для обязательных: `savegame.cpp:1947`), значит старые версии читают новые сейвы. Лимит
  секций — 64 (`save_sections.h:18`), всего сейва — 4 МиБ (`savegame.h:11`).
- **Повтор и turn oracle.** Директива привязана к ходу. При повторе подставляется
  записанная, модель не вызывается — `turn_oracle.cpp` продолжает работать как проверка.
- **Мультиплеер.** Модель хост-авторитарная: хост считает ход (`netturn.cpp:122`,
  `Host_Next_Turn` → `NEXTTURN::Next_Turn` в `:201`) и рассылает состояние
  (`Broadcast_Game_Data_Differential`, `:223`). LLM вызывает только хост; клиенты получают
  уже применённые изменения. Директивы, влияющие на игру, должны сериализоваться вместе с
  состоянием или применяться до рассылки.

## 5. Каталог идей по подсистемам

Обозначения: **Сложность** — объём кода; **Риск** — шанс сломать баланс или совместимость.

### 5.1 Смена цели и характера империи — первый кандидат

- **Сейчас:** `objectives` и `personality` выставляются при старте (`ken.cpp:134`, `:333`) и
  читаются модулями строительства, шпионажа и дипломатии.
- **LLM:** раз в N ходов или по триггеру выбирает новую цель (`militarist` после потери
  колоний, `technologist` при долгом мире) и, реже, сдвиг характера (например, `honorable`
  → `ruthless` после предательства союзника).
- **Применение:** запись в `s_player::objectives`/`personality` с ограничением частоты
  (не чаще раза в K ходов) и списком разрешённых переходов.
- **Сложность:** низкая. Поля уже есть и уже в сейве. **Риск:** низкий-средний.
- Это лучший первый модуль: проверяет всю цепочку (сводка → поток → HTTP → директива → сейв)
  почти без нового игрового кода.

### 5.2 Приоритеты производства

- **Сейчас:** правила производства AI (`production_rules`, документ
  `docs/content/manual/game-mechanics/ai-production-rules.md`) строят контекст в
  `AIBUILD::Build_Production_Context` (`aibuild.cpp:528`).
- **Свободные слоты:** метрики `METRIC_EXTENSION_1..7` (`production_rules.h:47-53`)
  объявлены, но нигде не используются.
- **LLM:** выставляет 3–5 весов («флот», «колонизация», «экономика», «оборона», «наука»).
  Движок кладёт их в extension-метрики, правила производства читают их как обычные метрики.
- **Сложность:** средняя. **Риск:** средний (баланс).
- **Сделано (слой 6 плана 10.9, `advisor rules_production`, выключен):** правило 120 ставит веса
  обороны (в войне или при позе «оборона»), еды (в дефиците; MAX при голоде), экономики (промышленник
  или убыток) и науки (технолог), если их не задало другое правило. Вес умножает классический вес
  автостроительства постройки своего вида: LOW 60 %, HIGH 150 %, MAX 200 %; все шесть весов директивы
  пишутся в метрики-расширения 1–6 правил производства (0 — KEEP … 4 — MAX).

### 5.3 Приоритеты исследований

- **Сейчас:** `aitech::AI_Tech_Select` (`tech_selection.cpp:42`) →
  `newtech::Choose_Tech_Application` (`newtech.cpp:437`), веса — `newtech::tech_priority`
  (`newtech.h:11-18`).
- **LLM:** смещение весов по направлениям (оружие, щиты, двигатели, планеты), например
  «нужна защита от ракет» после боя.
- **Сложность:** низкая-средняя. **Риск:** низкий.

### 5.4 Военные цели и внезапные атаки

- **Сейчас:** `AIMOVE::Move_AI` (`aimove.cpp:86`): атаки `Launch_Attacks` (`:267`), выбор цели
  `Find_Best_Attack_From_Star` (`:1562`), ценность колонии
  `Enemy_Colony_Worth_To_Player` (`:827`), внезапная атака `Launch_Sneak_Attack` (`:42`).
- **LLM:** выбирает «главного соперника» и «направление удара». Движок умножает ценность
  колоний этого игрока на коэффициент из директивы. Маршруты и состав флотов остаются за C++.
- **Сложность:** средняя. **Риск:** средний.
- **Сделано (слой 6 плана 10.9, `advisor rules_war_goals`, выключен):** ценность целей главного
  соперника директивы — 150 %, империи, с которой велено воевать, — 125 % в выборе атак
  оригинального ИИ (`Compute_Attack_Worthiness`, рядом с другими множителями советника).

### 5.5 Контр-дизайн флота и «память разведки» — самая заметная для игрока идея

- **Сейчас:** `Auto_Design_Ship` (`aidesign.cpp:1376`) собирает корабль по спискам
  приоритетов (`aidesign.cpp:20-124`: `shield`, `missile_defense`, `beam_defense`,
  `cloaking`…) и 8 профилям распределения места (`aidesign.h:10-19`, настраиваются в
  `specs/config/main.json5`, запись `ship_design_allocations`). Но:
  - набор защиты выбирается по тому, лучевое ли оружие **у игрока 0**
    (`defense_priority.human_beams` / `human_non_beams`, `aidesign.h:43-44`);
  - оружие подбирается против лучшего щита **первого живого игрока** по его **технологиям**
    (`aidesign.cpp:196-215`), а не по тому, что AI видел.
- **Новое — память разведки:** что империя X видела у империи Y (доля урона ракетами, лучами,
  истребителями; щиты; спецсистемы; абордаж). Заполняется из:
  - начала боя — `Load_Combat_Ship` (`combat_lifecycle.cpp:56`) вызывается для каждого корабля;
  - отчётов шпионов (новое правило, см. 5.7).
- **LLM:** по памяти разведки выбирает **против кого** строить, **доктрину** (анти-ракеты,
  анти-лучи, анти-абордаж, сбалансированно) и **профиль** корпуса.
- **Применение:** вместо `players[0]` подставляется выбранный соперник; доктрина выбирает
  таблицу защиты; профиль — `allocations.profiles`. Слоты по-прежнему расставляет
  `Auto_Design_Ship`, поэтому корабль не останется без двигателей или компьютера.
- **Перепроектирование:** `Keep_Ship_Designs_Up_To_Date` (`aidudes_ship_upgrades.cpp:6`).
- **Эффект для игрока:** один шаблон («ракетный эсминец») больше не выигрывает всю партию:
  через 5–10 ходов противник перестроит верфи под ПВО и помехи — но только если **видел**
  эти корабли.
- **Сложность:** средняя-высокая. **Риск:** средний (баланс, нужна настройка).

**Без LLM: решено и сделано 21.11.2026** (флаг `advisor rules_seen_ships`, код —
`src/game/advisor_intel.{h,cpp}`). Что нашлось в оригинале: две таблицы защиты
(`human_beams` и `human_non_beams`) совпадают, так что выбор «лучи у врага или нет» ничего не
меняет; защита корабля не зависит от врага вовсе.

- **Источник — бой.** Перед каждым боем (автобой и тактический бой проходят через одну точку,
  `COMBFIND`) каждая сторона запоминает корабли другой. Шпионы как второй источник — позже (5.7).
- **Память** для каждой пары «кто видел — чьи корабли»: потенциал урона по классам оружия (лучи,
  ракеты, торпеды, истребители, бомбы, особое; число стволов × максимальный урон), противоракетная
  защита (глушилки, поле молний, антиракеты, стволы с точечной защитой) и число кораблей. Раз в 10
  ходов всё умножается на 3/4: за 50 ходов от старых наблюдений остаётся четверть.
- **Угроза:** ракеты и истребители — не меньше половины урона → «ракеты» (или «истребители», если
  их больше, чем ракет); лучи и торпеды — не меньше 60 % → «лучи»; иначе угрозы нет.
- **Применение** (проектировщик, только империи советника, против врага из
  `Design_Reference_Enemy`):
  - защита: ответ на угрозу ставится в начало списка защитных систем, остальной список — в прежнем
    порядке (место ограничено, поэтому порядок решает, что попадёт на корабль). Против ракет —
    глушилки, поле молний, антиракеты, смещение; против истребителей — поле молний, смещение,
    инерционные системы; против лучей — жёсткие и многофазные щиты, отражающее поле, конденсатор
    щитов, инерционные системы, тяжёлая броня;
  - оружие: если у врага в среднем не меньше 2 единиц противоракетной защиты на корабль, ракетные
    и авианосные классы кораблей заменяются лучевыми (когда лазеры изучены).
- **Когда:** ИИ перепроектирует корабли при каждой новой технологии, поэтому ответ приходит через
  несколько ходов после боя, без лишних перепроектирований.
- **Сейв:** отдельная необязательная секция `ADVI`: пишется, только если советник включён и память
  не пуста; старые сборки её пропускают.
- **Детерминизм:** память не тянет случайные числа; с выключенным советником ничего не меняется.

### 5.6 Тактическая доктрина боя — без вызова LLM в бою

- **Сейчас:** тактический AI в `cmbtai.cpp`: ход корабля `Do_Auto_Ship_Turn` (`:141`),
  отступление `Retreat_Check` (`:324`), выбор цели `Choose_Target` (`:528`) /
  `Target_Ship_Value` (`:546`).
- **Почему не вызывать LLM в бою:** бой синхронный, ожидание заморозит экран.
- **LLM (заранее, на стратегическом проходе):** выбирает доктрину на ближайшие ходы —
  «держать дистанцию», «агрессивный штурм», «беречь флагман», «приоритет — транспорты».
  В бою доктрина работает как готовый набор смещений для `Retreat_Check` и `Target_Ship_Value`.
- **Сложность:** средняя. **Риск:** средний-высокий (тактика чувствительна к балансу).
- **Сделано (слой 6 плана 10.9, `advisor rules_tactics`, выключен):** доктрина выводится из позы
  директивы и характера, не хранится: наступление (новая или текущая война) — отступать только при
  угрозе врага в 8 раз больше своей (оригинал — 5); заключение мира — «держать дистанцию», 3;
  оборона — сначала корабли с десантными капсулами (ценность цели ×3); благородные и миролюбивые —
  «беречь флагман»: флот с офицером на борту отступает при 3. Крюки — `Retreat_Check` и
  `Target_Ship_Value` (`cmbtai.cpp`); арифметика оригинала для 5 сохранена.

Триггер ставит внеочередной запрос в очередь (с ограничением частоты на империю).

|---|---|---|
| Колония уничтожена | `BOMB::Destroy_Colony` (`colony_lifecycle.cpp:46`) | цель, военная позиция, обиды |
| Колония захвачена | смена владельца в `invasion.cpp` (~`:520`) | цель, позиция, обиды |
| Корабли противника увидены в бою | `Load_Combat_Ship` (`combat_lifecycle.cpp:56`) | память разведки → доктрина флота |
| Исследована технология | выбор применения: `tech_selection.cpp:22`, `techinit.cpp:391` | доктрина, исследования |
| Построено здание / база | `ERICNET::Add_Building` (`ericnet.cpp:312`), из производства — `colcalc.cpp:3726` | у соседей: шпионаж, оборона |
| Первый контакт | `diplomac::Determine_First_Contacts` (`diplomac.cpp:882`) | позиция к новой империи |
| Объявлена война / заключён мир | `Declare_War` (`diplomac.cpp:1082`), `Declare_Peace` (`:1816`) | цель, союзники, обиды |

Триггер не вызывает LLM сразу: он помечает империю «нужно пересмотреть», а вызов уходит в
конце хода вместе с остальными запросами.

## 7. Сложность и бюджет вызовов

Уровень сложности игры (`MOX::settings.game_difficulty`) задаёт частоту.

| Сложность | Плановый опрос | Триггеры | Модель |
|---|---|---|---|
| Лёгкая | раз в 5 ходов | только крупные (потеря колонии, война) | 4B |
| Средняя | раз в 3 хода | все, с ограничением частоты | 4B |
| Сложная | каждый ход | все | 4B каждый ход + большая модель раз в 5–10 ходов |
| Невозможная | каждый ход | все + советник учитывает память разведки глубже | то же |

Бюджет хода: не больше M запросов (например, по одному на империю плюс триггерные) и общий
таймаут. Если очередь не успевает, приоритет у триггерных запросов и у империй, которые
давно не получали директиву.

## 8. Модели и роли

Две роли можно закрепить за одной моделью (разные системные промпты) или за разными моделями.
У `llama-server` есть режим роутера (`--models-dir`, `--models-preset`), который подгружает
модель по имени из запроса.

| Роль | Требования | Кандидаты |
|---|---|---|
| **Стратег** | строгий JSON, быстро, без «размышлений» | Qwen3-4B-Instruct-2507, Qwen3.5-4B, Gemma 4 E2B, Sharp-Spark-X2.6-4B |
| **Рассказчик** | хороший русский и английский, стиль | Qwen3.5-4B, Gemma 4 E2B; эксперимент: Qwen3-4B-RPG-Roleplay-V2, Qwen3-8B-DND |
| **Большая стратегия** (редко) | глубже рассуждает, допустимы десятки секунд | Qwen3.6-35B-A3B (MoE, эксперты в RAM) |

Конкретный выбор для RTX 3050 Ti 4 ГБ, скрипты и план бенчмарка —
в [RTX_3050_ti/README.md](RTX_3050_ti/README.md). Второй ноутбук (RTX 5070, 8 ГБ) для офлайн-задач
и моделей тяжелее 4B — [RTX_5070/README.md](RTX_5070/README.md).

**Итоги бенчмарка 20.11.2026** ([подробно](RTX_3050_ti/benchmark-2026-11-20.md)): 4B-модели
хорошо пишут и посредственно решают; формат ответа влияет на качество решений сильнее выбора
модели (свободный список дипломатических действий → шум; отношение к каждой империи →
в разы меньше грубых ошибок). Предложение для 4 ГБ: Qwen3.5-4B на обе роли; RPG-4B и DnD-8B
исключены. Схема v2, проверки директив в движке и ограничение меню характером — предложения,
ждут решения.

Специализированных маленьких моделей «для стратегических решений» на Hugging Face не нашлось
(ноябрь 2026); D&D- и roleplay-дообучения не публикуют оценок качества. Практичный путь —
модель общего назначения + закрытое меню + JSON-схема.

## 9. Риски и как их гасить

| Риск | Что делать |
|---|---|
| Задержка, «зависание» хода | асинхронно, применять на следующем ходу, запасной вариант — исходный AI |
| Модель выдаёт невалидный ответ | JSON-схема → грамматика; проверка в движке; ошибка = «без изменений» |
| **Упрямство**: LLM меняет стратегию **реже** обычного AI (данные Vox Deorum, раздел 11) | триггеры-«пинки»; в промпте — характер лидера и явный вопрос «что изменилось с прошлого раза»; минимальная частота пересмотра |
| Самообман («выигрываем войну», проигрывая) | движок даёт честные оценки сил в сводке; модель не считает сама |
| Повторы и однообразные реплики | сэмплинг по рекомендации модели, `presence_penalty`, в промпте — последние реплики, чтобы не повторяться |
| Смешение языков в русском тексте | не завышать `presence_penalty`; модель с хорошим русским для рассказчика |
| Поломка детерминизма | LLM не трогает игровой RNG; директивы — записанный ввод в сейве |
| Мультиплеер | вызывает только хост; результаты идут вместе с состоянием |
| Инъекции через текст игроков | имена (до 20 символов) не опасны; свободный текст игроков в промпт стратега не попадает — в бенчмарке ему подчинились 4 конфигурации из 7 |
| Нагрев ноутбука, троттлинг | под долгой нагрузкой 88–90 °C, частота GPU падает втрое → переход на уровень B (решение 20.11.2026) |
| Размер сейва | лимит на память разведки и обид; всего сейва 4 МиБ (`savegame.h:11`) |
| Баланс | все смещения ограничены коэффициентами из конфига; флаг «выкл» |
| Upstream | `CONTRIBUTING.md` требует обсуждать изменения геймплея и раскрывать участие AI; держать модуль отдельно (`src/game/llm/`), выключенным по умолчанию |
| Лицензии моделей | модели не входят в репозиторий; у кандидатов Apache-2.0 / MIT; у RPG-модели в карточке тег NSFW |

### 10.2 Этап 2 — советник на правилах (спецификация)

Правила читают **только вид империи** (`s_empire_view`): советник знает то же, что знает
империя. Директива правил живёт `rules_period` ходов (по умолчанию 5), потом правила
пересчитываются. Каждое сработавшее правило пишет в журнал номер, имя и числа.

Обозначения: «война с X» — `treaty` 4–6; «союз» — 2; сила своих —
`self.fleet_strength`, сила X — `visible_fleet_strength`.
**Проигрываемая война с X:** видимая сила X больше полуторной нашей, или наши потери
кораблей от X не меньше удвоенных потерь X (`our_ship_losses >= 2 × max(1, their_ship_losses)`).
**Главный враг:** среди тех, с кем война, — с наибольшим `10 × our_colony_losses +
our_ship_losses` (при равенстве — меньший номер игрока).

**Цель империи** (первое сработавшее правило; характер может изменить выбор):

| № | Имя | Условие | Цель | Прочее в директиве |
|---|---|---|---|---|
| 101 | famine | `food_surplus <= -3` (дефицит 1–2 у ИИ бывает постоянно — самоигра 20.11.2026) | ECOLOGIST | — |
| 102 | losing_war | есть проигрываемая война | MILITARIST; у PACIFIST — DIPLOMATIC | main_rival = этот враг; posture DEFEND (у PACIFIST — MAKE_PEACE) |
| 103 | at_war | есть война, характер AGGRESSIVE / RUTHLESS / XENOPHOBIC / ERRATIC, цель не MILITARIST | MILITARIST | main_rival = главный враг; posture ATTACK_CURRENT_ENEMIES |
| 104 | room_to_grow | **снято 20.11.2026:** смена цели на EXPANSIONIST почти не влияет на экспансию ИИ (10.3); вместо него — правило 301 | — | — |
| 105 | peace_dividend | ход 50 и позже, есть хотя бы один контакт, нет войн, ни с кем отношения не ниже −25, цель MILITARIST (на ходу 0 «мир со всеми» — это просто отсутствие контактов) | TECHNOLOGIST; у HONORABLE и PACIFIST — DIPLOMATIC; у RUTHLESS — INDUSTRIALIST | — |

**Шпионы** (независимо от цели):

| № | Имя | Условие | Цель шпионов | Миссия |
|---|---|---|---|---|
| 201 | spy_war | война с X и у нас есть шпионы у X (главный враг, если таких несколько) | X | SABOTAGE; у HONORABLE и PACIFIST — STEAL_TECH |
| 202 | spy_rival | нет войн; среди контактов, где у нас есть шпионы, — с самыми низкими отношениями | он | STEAL_TECH |

Правило экспансии (этап 2в) — независимо от остальных, как и правила шпионов:

| № | Имя | Условие | Вес |
|---|---|---|---|
| 301 | expand | известна хотя бы одна свободная обычная планета на посещённой звезде в пределах дальности кораблей (`free_planets_in_reach > 0`) и нет проигрываемой войны (правило 102); при голоде (101) правило работает | `weights[COLONIZATION] = HIGH` |

Если ни одно правило не сработало, директивы нет (империя играет по исходному AI).

**Применение** (`advisor_apply.h`), каждое — под своим флагом:

- `rules_objectives`: цель пишется в `s_player::objectives` не чаще раза в
  `objective_min_turns` ходов (по умолчанию 10); момент последней смены хранится в сейве.
- `rules_spies`: в `Allocate_AI_Spies` вес цели из директивы умножается на
  `spy_target_weight_percent` (по умолчанию 300 %), миссия заменяется на выбранную
  (0 — шпионаж, 1 — саботаж). Число обращений к игровому генератору случайных чисел не
  меняется.
- `rules_expansion` (этап 2в): пока у империи активная директива с весом колонизации HIGH,
  планировщик производства ИИ держит в постройке один колонизатор. Если колонизатора нет, а цель
  в пределах дальности есть, он ставится первым в очередь самой производительной колонии
  (ценность производства не меньше 10, `ai_empire_production.cpp`). Недостроенный колонизатор
  не сносится ни при нехватке денег, ни при очистке очереди после новой технологии
  (`aidudes.cpp`).
- Флаги механик по умолчанию включены, но действуют только при `advisor enabled = true`.

### 10.3 Самоигра 20.11.2026: почему смена цели почти ничего не даёт

**Стенд:** 64 партии по 100 ходов — 8 сидов × сложность Average и Hard × 4 варианта, 5 империй
ИИ, средняя галактика. Варианты:

- «наблюдение» — советник включён, механики выключены (игра идёт как без советника, журнал пишется);
- «советник» — правила этапа 2 как есть;
- «крюки» — временный эксперимент в планировщике производства ИИ, без советника;
- «советник + крюки».

Временный код эксперимента из движка удалён.

**Итог (среднее по сидам, сумма по 5 империям на 100-м ходу):**

| Вариант | Average: колонии | Hard: колонии | Население (Avg / Hard) | Промышленность (Avg / Hard) |
|---|---|---|---|---|
| наблюдение | 14,2 | 15,8 | 108 / 110 | 203 / 246 |
| советник | 14,5 (лучше в 2 сидах из 8, хуже в 1) | 15,4 (лучше в 3, хуже в 4) | 107 / 109 | 188 / 240 |
| крюки | **18,0** (лучше во всех 8) | **21,8** (лучше во всех 8) | 117 / 125 | 207 / 259 |
| советник + крюки | 18,4 | 21,0 | 117 / 122 | 207 / 256 |

**Почему смена цели — слабый рычаг.** Поле `objectives` почти не управляет экспансией ИИ; её
ограничивает планировщик производства (`ai_empire_production.cpp`):

1. колонизатор рассматривается, только когда колония простаивает (около 30 % ходов);
2. строить его может лишь колония с «ценностью производства» не меньше 20 — почти всегда только
   столица; на сложности Tutor (по умолчанию в oracle) столица не дотягивает весь первый век;
3. в постройке держится один колонизатор на империю, строится он около 20 ходов;
4. **ИИ сам сносит недостроенные колонизаторы:** при нехватке денег
   (`bc + surplus_bc < total_maintenance`) и при очистке очереди после новой технологии
   (`aidudes.cpp`, `Clear_Build_Queues_If_New_Tech`). На Average в одной партии снесено 28
   колонизаторов в постройке, колонизировали 8 (5 из них — стартовые).

Цель EXPANSIONIST меняет лишь пункт 3 (с шансом 1/5 разрешает второй колонизатор) и порог
колониальной базы. Свободные планеты в пределах дальности при этом есть у всех (4–13 у каждой
империи).

**Крюки эксперимента:** (а) не сносить колонизатор в постройке ни из-за денег, ни из-за новой
технологии; (б) если у империи нет колонизатора, а цель в пределах дальности есть — поставить
колонизатор первым в очередь самой производительной колонии.

**Побочные эффекты правил этапа 2:** на Average промышленность ниже на 7 %, на Hard сила флота
выше на 35 % (чаще MILITARIST по правилам 102/103); в среднем 7 смен цели за партию на 5 империй.

**Вывод для дизайна:** советник должен влиять на ИИ через крюки в планировщике, а не только
через `objectives` — так же, как уже сделано для шпионов (`Spy_Target_Weight_Percent`).
**Решено 20.11.2026 — этап 2в:** крюк экспансии под флагом `advisor rules_expansion`; правило
104 снято, его место заняло правило 301 (вес колонизации), см. 10.2.

**Проверка этапа 2в** (тот же стенд: 8 сидов × Average и Hard; сумма по 5 империям на 100-м ходу):

| Вариант | Колонии (Avg / Hard) | Население | Промышленность | Наука | Казна | Смен цели за партию |
|---|---|---|---|---|---|---|
| наблюдение | 14,2 / 15,8 | 108 / 110 | 203 / 246 | 159 / 173 | 1193 / 1883 | 0 |
| **советник целиком** | **18,4 / 21,5** | 118 / 125 | 216 / 266 | 159 / 179 | 1584 / 2295 | 3,0 / 3,4 |
| советник без крюка экспансии | 14,4 / 14,9 | 107 / 109 | 199 / 236 | 160 / 158 | 1163 / 1431 | 2,4 / 3,4 |
| только крюк экспансии | 17,6 / 20,5 | 115 / 124 | 207 / 261 | 150 / 180 | 1848 / 2238 | 0 |

- Советник целиком лучше наблюдения по колониям **во всех 16 парах партий**: +30 % на Average,
  +36 % на Hard; растут население, промышленность и казна, наука не падает.
- Без крюка экспансии советник почти не отличается от наблюдения, а на Hard проигрывает в науке
  (−9 %) и казне (−24 %) при флоте +45 % — это эффект правил 102/103.
- Смен цели стало вдвое меньше (3 вместо 7), потому что правило 104 снято.

ходах: **ровно никакой разницы** — за это время у ИИ почти нет различий в щитах и оружии. Крюк
оставлен (безвреден), пользу проверить на длинных партиях и в игре против человека.

**Византийская доктрина** (`advisor rules_doctrine`, 10.6): правило 402 «враг моего врага» (союз с
теми, кто воюет с нашими врагами), «купить мир» при проигрываемой войне (правило 102 ставит позицию

отношения — небольшой сдвиг к миру во всех решениях о войне, мире и договорах).

**Исправлена ошибка оригинала, ронявшая отладочную сборку:** в отчёте о сорванном отступлении
(`combfind.cpp`) повторное чтение позиции уже уничтоженного корабля давало для игрока 1 индекс −1 —
запись перед массивом на стеке («Run-Time Check Failure #2 — Stack around the variable 'report' was
corrupted»). Теперь перенаправляются только выходящие за массив индексы; всё, что раньше попадало
внутрь массива, ведёт себя как прежде (turn oracle зелёный). В отладочной сборке при работе turn
oracle (и при `ORION2RE_SILENT_CRASH=1`) ошибки C runtime пишутся в stderr, и процесс завершается с
кодом 3 вместо модального окна, которое останавливало стенд.

### 10.4.5 Память боёв, чужая война и стратегия по фазам: 400 ходов (21.11.2026)

Сборка 0b3829d, сиды 1–8, Average и Hard. Контроль: вариант с доктриной 61, перезапущенный новой
сборкой, сыграл те же партии, что и в `doctrine400` (−0,3 и +0,5, те же счёты сидов), — значения по

|---|---|---|---|

| + чужая война (125) | +4,6 (+9,0 / +5,5 / +6,1 / −2,4) | 6 | 4 |
| + фазы | +4,1 (+9,9 / 0,0 / +6,0 / +0,6) | **7** | 6 |
| + фазы и чужая война | −4,0 (−8,5 / −10,9 / +7,9 / −4,4) | 3 | 6 |

против 44 %, промышленность +58 %, флот вдвое больше, наука −27 %; на Average рост скорее ниже
(колоний 26,4 против 31,0). Совет выигрывается чаще: на Average в 6 партиях из 8 против 5.

**Почему фазы почти не помогли против обычного ИИ.**
1. Правило 406 срабатывает редко: лидерство заявляется только со шпионами у каждого контакта (без
   них в первых партиях «лидером» оказалась империя с одной колонией). На Average — меньше 1 %

2. Правило 407 поднимает империи советника против любого претендента на победу, в том числе против

   но на стенде «умные против обычных» это работает против команды «умных».
3. С чужой войной (405) фазы складываются плохо: больше войн против соседей, хуже итог.

**Решение:** по умолчанию всё остаётся как было (доктрина 61, фазы и бит 64 выключены, память боёв
включена). Правило 407 — защита от победы человека в совете — проверяется только в игре с человеком.

### 10.4.6 Кто побеждает: совет без человека, 400 ходов (21.11.2026)

Стенд `victory400` (сборка 0d20fcb): совет собирается и без человека (`gameplay

побед на «место» империи (каждая играет за себя): победы империй советника / их мест против побед
обычного ИИ / его мест (`run/victory.py`).

**Совет делает партии решёнными.** Average: советник у всех — победитель в 6 партиях из 8 (5 советом,
1 завоеванием, в среднем к 246-му ходу); только обычный ИИ — в 2 из 8 (оба завоеванием, к 369-му).
Hard решается редко: 1–3 партии из 8.

| Вариант | Победы советника | Победы обычного ИИ |
|---|---|---|
| доктрина 61 | 7 (8,8 %) | 7 (8,8 %) |
| + фазы (всё) | 7 | 7 |
| + только лидер (406) | 7 | 7 |
| + только против победителя и голосование (407, 4) | 9 (11,3 %) | 7 |

по силе коалиции, а не одной империи; (2) лидеру, которому до 2/3 недалеко, — мир и рост населения
вместо новых войн.

### 10.4.7 Коалиционная война: 400 ходов (21.11.2026)

Стенды `coalition400` (правило 408, первая версия, сборка 47d7ef9) и `coalition2` (вторая: слабый
сосед претендента вступает, только если помощь рядом, сборка 02e3662); совет без человека, партии до
первой победы, сравнение с `victory400`. Контроль `h2h-21` новой сборкой сыграл те же партии.

**Правило работает, но срабатывает редко.** В смешанных галактиках на Average коалиция собиралась
2–6 раз за 8 партий, на Hard — 8–11 (а партии на Hard почти не решаются). Вторая версия меняет
поведение: на Hard примерно половина решений о коалиции — «затаиться» (сосед слаб, помощи рядом
нет), на Average — единицы. Итоги партий при этом почти те же, что без коалиции: в смешанных
галактиках советник и обычный ИИ по-прежнему побеждают примерно одинаково часто на место империи,
разница — одна партия.

**Почему.** Претендент проскакивает «половину голосов» одним завоеванием: в сиде 1 (Average)
империя 0 за 7 ходов выросла с 39 % голосов до 66 %, захватив соседа, и победила на первом же
совете. Кроме того, без шпионов размер соседа известен лишь по увиденным колониям.

**Что дальше:** (1) звать коалицию раньше — по темпу роста претендента или с 40 % голосов, — и
держать шпионов у крупнейшего соседа; (2) военные донесения (mechanics.md 3.1.1) вместо
«союзник в досягаемости».

### 10.4.13 «Разделяй и властвуй» v2: 400 ходов (22.11.2026)

Почему v1 почти ничего не меняла: оригинал (`Frame_Another`) и сам подставляет сначала врагов

### 10.5 Теория игр: дорожная карта (решено 20.11.2026)

Порядок: сначала стенд «умные против обычных» (без него улучшения войны и дипломатии не
измерить: если все империи стали одинаково хитрее, сумма по галактике не меняется), затем
методы 1 и 2; остальные — в своих этапах.

| # | Метод | Суть для MOO2 | Этап |
|---|---|---|---|
| 0 | **Стенд «умные против обычных»** | советник включён только у части империй (маска игроков); сравнивается доля колоний, населения и выживаемость умных и обычных на одних и тех же сидах | 3 |

### 10.6 Византийский «оперативный кодекс» как доктрина ИИ (20.11.2026)

Источник: Э. Люттвак, «Стратегия Византийской империи», заключение — семь правил империи, которая
продержалась дольше всех. Соответствие механикам советника:

| Правило (пересказ) | Что уже есть | Что добавить |
|---|---|---|
| I. Избегай войны, но всегда будь готов к ней; готовность нужна, чтобы не пришлось сражаться | решающий перевес в атаке (10.4.1) | **сдерживание:** выше порог объявления войны всем, кроме лидера и главного соперника (с учётом характера империи), при этом держать оборону колоний |
| II. Разведка: шпионы у врага, постоянное наблюдение за его перемещениями и намерениями | разведсеть 2б: наблюдатели у каждого контакта, сведения от шпионов в виде советника | — |
| III. Избегай большого сражения, кроме крайне выгодных условий | решающий перевес 150 %, Ланчестер | — |
| IV. «Не-битва»: не встречай превосходящие силы в лоб, бей отдельные слабые отряды | — | **набеги:** выше ценность слабо защищённых целей (аванпосты, малые колонии, транспорты) при выборе атаки |
| V. Побеждай союзами: во время войны дипломатия важнее всего; лучшие союзники — союзники врага | коалиция против лидера (правило 401) | **враг моего врага:** при войне с X — дружелюбие к врагам X и к его союзникам (переманить), выше оценка договоров с ними |
| VI. Подкуп — самый дешёвый путь к победе | — | **купить мир:** при проигрываемой войне (правило 102) — мир раньше и с данью; позже — подкуп лидеров (mechanics.md 3.2.3) |
| VII. «Реляционный» способ: обходи силу врага, бей по его слабостям; не уничтожай врага до конца — сегодняшний враг завтра может стать союзником | контр-дизайн флота (оружие против щитов реального врага) | **не добивать:** почти разбитому врагу, если он не лидер, — мир, чтобы он остался противовесом |

Сделано 20.11.2026 под флагом `advisor rules_doctrine` (10.4.2): I — сдерживание (без явного
отношения небольшой сдвиг к миру); V — правило 402 «враг моего врага»; VI — «купить мир» при
проигрываемой войне; IV — набеги (атака незащищённой колонии ценится вдвое выше); VII — правило 403
«не добивать» (почти разбитому врагу, если он не лидер, — дружелюбие и мир).

**Полная доктрина (21.11.2026, ночь).** Стенд на 400 ходов (10.4.3) показал, что первая версия
взяла только половину правила I: «избегай войны» — да, «но всегда будь готов» — нет. Советник
выставлял вес флота, но ни один крюк движка его не читал, а правило 105 («мирный дивиденд»)
переводило мирных милитаристов на технологии; флот «умных» в смешанной галактике был вдвое меньше,
чем у обычного ИИ в тех же слотах. Теперь доктрина — шесть частей, каждая со своим битом в
`advisor doctrine_parts`, чтобы мерить их по отдельности (по умолчанию 61 — все, кроме
готовности: она стоила экспансии, 10.4.4; с 22.11.2026 — 189, добавлена дань, 10.4.12):

| Бит | Правило | Что делает |
|---|---|---|
| 1 мир | I | правило 404 «мир от силы»: сдвиг к миру (отношение NEUTRAL, +20) только к соседям, воевать с которыми дорого — их боевая сила не меньше 2/3 нашей (по Ланчестеру), кроме главного соперника; к явно слабым — без сдвига, оппортунизм оригинального ИИ остаётся |
| 2 готовность | I | флот по самому сильному соседу, как у милитариста, при любой цели (`aibuild.cpp`, цель боевой силы) — соразмерно угрозе: слабые соседи требуют мало; правило 105 не снимает цель «милитарист», пока у соседа больше боевой силы |
| 4 набеги | IV | атака незащищённой колонии ценится вдвое выше |
| 8 союзы | V | правило 402: дружба с врагами наших врагов и **ухаживание за союзниками врага** (отношение FRIENDLY к тем, кто в союзе с нашим врагом, — переманить) |
| 16 купить мир | VI | при проигрываемой войне — позиция MAKE_PEACE, мир с соперником на 30 ходов раньше |
| 32 не добивать | VII | правило 403 |
| 128 мир с данью | VI | проигрывающая империя (позиция MAKE_PEACE против главного соперника) предлагает дань: победитель мирится на 20 ходов раньше; после мира проигравший платит 5 % производства и перестаёт, когда его флот в 1,5 раза сильнее флота получателя (Византия платила аварам и перестала, окрепнув). Включено по умолчанию после замера (10.4.12): купленный мир держится дольше, плательщик чаще выживает |
| 256 разделяй и властвуй | V | когда шпион при краже или саботаже кого-то подставляет, империя советника подставляет своего главного соперника, а при стратегии по фазам — лидера голосования в совете (голоса публичны, а нейтральный член совета голосует по отношениям); союзника — никогда, иначе — кого выбрал оригинал (он и сам подставляет сначала врагов, союзников в последнюю очередь). v1 подставляла самого сильного соседа жертвы без оглядки на договоры — могла подставить нашего союзника. Случайные броски оригинала не меняются. По умолчанию выключено; замер v1 — 10.4.12 (гнев перенаправляется, войн не прибавляется), v2 — 10.4.13 (бьёт по претенденту точнее и сильнее, но редко) |
| 64 чужая война | III–V, VII | правило 405 (ниже): защитить слабого от опасного нападающего, присоединиться к войне против слабого соседа или напасть на слабого соседа, когда тыл спокоен; с битом 32 — щадить разбитого врага, только пока он нужен как противовес. По умолчанию выключено до замера |

Правила II (разведка), III (решающий перевес) и контр-дизайн из VII — под своими флагами
(`rules_spies`, `rules_lanchester`, `rules_counter_design`, все включены по умолчанию). Не сделано:
мир «с данью» (VI) — между ИИ мир заключается без согласия другой стороны, а с игроком нужен
интерфейс предложения; подкуп лидеров ждёт механик шпионажа (mechanics.md 3.2.3).

**Чужая война (правило 405, бит 64; решено с автором 21.11.2026).** Вопрос автора: не слишком ли
дружелюбны империи — слабого соседа без сильных покровителей можно смело добить, а если рядом
крупный сосед, он вступится за слабого или отхватит часть его планет. На стенде 400 ходов у
«умных» 0,2 войны против 0,5 у обычного ИИ: правило 404 мирит с опасными соседями, а к войне со
слабыми ничто не толкает. «Атаки по случаю» оригинала (`Set_Opportunity_Attacks`) ищут цели только
среди людей, а решение о войне (`npcdiplo.cpp`) учитывает третьи стороны тоже только людей. Чужих
войн советник не видел: 402 работает, только когда воюем мы сами, 401 — только против лидера.

Сила — боевая мощь по Ланчестеру из вида империи (что видим и что сообщают шпионы). «Опасен» — не
меньше 2/3 нашей мощи (как в 404); «слаб» — не больше половины нашей и колоний не больше, чем у
нас. **Тыл спокоен**, если каждый опасный для нас контакт связан с нами пактом или союзом. Правило
трогает только контакты, которым правила выше (401–403) не задали отношения, и не трогает тех, с
кем у нас пакт или союз: слово держим (репутация — валюта Византии; дипломатическая память
помнит предательства).

| Случай | Решение | Правило Люттвака |
|---|---|---|
| X воюет с Y; Y много слабее X, X опасен нам, Y нам не опасен | **защитить:** Y — FRIENDLY (договоры легче, сами не нападём), X — WARY, X — главный соперник, если его нет (шпионы и проекты кораблей против него) | V, VII: баланс, буфер |
| X воюет с Y; Y слаб для нас и в досягаемости, X нам не опасен, тыл спокоен, у Y нет опасных союзников | **шакал:** Y — HOSTILE (порог войны ниже на 100): флот Y занят, его колонии у нашей границы дёшевы | III, IV |
| Y слаб для нас, в досягаемости, ни с кем не воюет, тыл спокоен, у Y нет опасных союзников | **добыча:** Y — HOSTILE | III: бой только в выгодных условиях |
| X и Y примерно равны | не вмешиваться: пусть обескровят друг друга | «третий радуется» |

**Не добивать — только когда нужен противовес:** с битом 64 правило 403 щадит почти разбитого
врага, только если есть другой опасный для нас контакт (тогда слабый нужен как противовес и буфер);
если такого нет, слабого добиваем. **Смена сторон** получается сама: правила пересматриваются каждые
`rules_period` ходов, и когда бывший слабый станет сильнее, защищать будут уже его противника.
Предательства союзника в правиле нет: византийский ответ — сменить сторону, а не нарушить слово.

### 10.7 Стратегия по фазам: играть на победу (решено с автором 21.11.2026)

Вопрос автора: цель MOO2 — победа, а кодекс Люттвака — стратегия *выживания* империи среди многих
сильных соседей; не слишком ли он пассивен? Да: к 400-му ходу у «умных» 0,1–0,2 войны, галактика
застывает, никто никого не добивает. MOO2 выигрывают завоеванием, советом или Антаресом. Совет
(`council.cpp`): голоса — население / 10 с округлением вверх; кандидаты — две крупнейшие империи;
победа — 2/3 всех голосов; союзник голосует за союзника всегда, воюющий — никогда, остальные — по
отношениям, доверию, нарушенным договорам, пакту (+50), торговому и научному договорам (+25).
Совет собирается каждые 25 ходов с 25-го, если живы хотя бы три империи и занята половина звёзд, —
и в оригинале **никогда в партиях без человека** (`nextturn.cpp`: `RUSS::all_ai_game == 0`).

**Цель — «Игра престолов»** (уточнение автора): каждая империя играет за себя против всех, включая
человека и других империй советника; партия кончается, когда совет выбирает одного лидера или кто-то
уничтожает всех остальных. Поэтому главная мера стенда — **как часто побеждает каждая империя**, а не
доля «команды умных».

**Совет без человека** (флаг `gameplay council_without_humans`, по умолчанию выключен; код —
`council_ai.h`, `council.cpp`). В партии без людей совет собирается по тому же расписанию и условиям,
без экрана: те же кандидаты, члены и порядок голосования (значит, те же броски `game_random`), те же
последствия голосов для отношений и то же правило 2/3; голосуют все как компьютерные империи;
избранный побеждает, как если бы решение приняли (`council_winner`, `won_council_vote`). Партия без
людей тогда идёт до первой победы — совет, последняя выжившая империя или Антарес, — turn oracle
останавливает запись на ней и печатает `oracle: victory <совет|завоевание|антарес> player N at
stardate S`.

Византийская дипломатия — это как раз то, что выигрывает совет (союзы, договоры, доверие). Нужна
не замена доктрины, а фазы с целью наверху (флаг `advisor rules_phases`, по умолчанию выключен до
замера; части — `advisor phase_parts`: 1 лидер, 2 против победителя, 4 голосование, 8 коалиционная
война, 16 «вступить последним», 32 военные донесения; с 100-го хода):

| Фаза | Когда | Поведение |
|---|---|---|
| Экспансия | есть свободные планеты | как раньше (301, 501) |
| Одна из равных | нет перевеса | византийская доктрина (401–405) |
| **Лидер, «Рим»** (правило 406) | колоний у нас не меньше 3 и в 1,5 раза больше, чем у каждого контакта; каждый контакт известен через шпионов или широкую разведку карты (половина звёзд) и его колонии мы видели; достаточно одного контакта | флот (вес флота HIGH → крюк готовности: флот по сильнейшему соседу); мир с сильнейшей из остальных империй (NEUTRAL: один фронт); остальные — FRIENDLY, самая «голосистая» из них — ALLY (союзник голосует всегда); **по одному** завоёвываем слабых соседей (сила не больше половины нашей, в досягаемости, известны через шпионов, без договора с нами): WAR, позиция START_NEW_WAR, главный соперник; слабых врагов, с которыми уже воюем, — до конца; правило 403 не щадит. Если наши голоса с союзниками уже ≥ 2/3 — новых войн нет: ждём совета |
| **Коалиционная война** (правило 408, часть 8; два контакта и больше) | у кандидата совета **сам по себе** (без союзников) не меньше 2/5 известных голосов — или не меньше трети, если он лидирует по голосам и уже воюет с кем-то другим («на марше»); известных голосов не меньше 15. Первая версия ждала половины и почти не срабатывала: претендент проскакивал её одним завоеванием (10.4.7). Шпионы идут к лидеру по голосам, если у нас их там нет | ему — WAR и главный соперник (кроме нашего союзника); тем, кто уже с ним воюет, — ALLY; остальным — FRIENDLY (один фронт); вес флота HIGH. **Кто вступает** (замечание автора: малый сосед, вступивший один, погибнет первым): далёкая империя — всегда (война дешёвая, а воюющий никогда не голосует за врага); сосед претендента — если его сила не меньше трети силы претендента или вместе с союзниками, которые уже воюют с претендентом и находятся в нашей досягаемости, не слабее его; иначе — и если флот претендента неизвестен (нет шпионов) — затаиться: NEUTRAL, пересмотр через 5 ходов. Координат флотов в виде империи нет, поэтому «войска рядом» — это союзники в досягаемости. **Вступить последним** (часть 16; замечание автора: в «Игре престолов» побеждают те, кто влез в драку последним): «безжалостные», «непредсказуемые» и «миролюбивые» лидеры затаиваются (NEUTRAL), пока претендента не перевешивают те, кто уже с ним воюет (сумма их боевой мощи не меньше его), — и тогда вступают добивать; если у претендента уже 3/5 голосов, ждать нельзя. «Агрессивные», «ксенофобы» и «благородные» вступают сразу. **Ожидание — это подготовка** (замечание автора: «чего ждать?»): ждущий строит боевой флот и транспорты с десантом (вес флота MAX → готовность и `Invasion_Transports`, 4 транспорта под обычными ограничениями ИИ), держит претендента главным соперником (шпионы, проекты кораблей) и вступает с готовым ударом; вступив, продолжает строить транспорты. **Военные донесения** (часть 32, mechanics.md 3.1.1): «помощь рядом» — это то, что враги претендента сообщают о своих силах у наших колоний, с поправкой на доверие к ним; без этой части — их флоты в досягаемости. Если с ним воюет ещё кто-то (совместная война), движок считает силу коалиции при решении о войне (`Coalition_Percent` в `Fleet_Strength_Comparison`, до 400 %), атаки на него не требуют решающего перевеса, его колонии — цели вдвое ценнее. Лидер, у которого у самого 2/5 голосов, ждёт такой коалиции: новых завоеваний не начинает, держит флот и растёт в мире |
| **Против победителя** (правило 407, два контакта и больше) | у кандидата совета (одна из двух империй с наибольшим числом голосов) его голоса с голосами союзников — не меньше 3/5 известных и не меньше 10 (голоса второго кандидата не в счёт: кандидат голосует за себя) | он — HOSTILE (WARY, если он наш союзник), его союзников переманиваем (FRIENDLY), он — главный соперник; в голосовании совета советник голосует по этим отношениям (`Council_Vote_Bias` в `Vote_Check`) |

Население соседа: через шпионов — точное, без них — известные колонии × наше население на
заселённую колонию (низкая достоверность); о ком не знаем ничего, тот считается таким же большим, как
мы. Как настраивали по стенду (`phases400`, 10.4.5):
- первая версия заявляла лидерство по индексу силы (с флотом) — «лидером» оказалась империя с одной
  колонией: без шпионов флот соседа — лишь то, что сканеры видят в этот ход;
- вторая требовала шпионов у каждого контакта — лидерство заявлялось в 5 % ходов на Average, а
  приказы о завоевании были редки; при этом когда правило срабатывало, оно работало: из 53 приказов
  34 закончились войной в течение 50 ходов, цели потеряли 28 колоний, 9 из них уничтожены, лидеры
  прибавили 143 колонии;
- теперь лидерство — по колониям (совет считает население, а не корабли): так оно заявляется вдвое
  чаще; для цели завоевания шпионы по-прежнему нужны (её флот должен быть известен);
- правило 407 на половине голосов поднимало всех против любого естественного лидера; теперь — 3/5 и
  хотя бы 10 голосов («2 из 4 голосов» на 100-м ходу были шумом).

Человек — такой же участник: если к победе подходит он, против него поднимаются все; если подходит
другая империя советника — тоже.

### 10.8 Расовые доктрины и каталог стратегий (решено с автором 21.11.2026)

**Зачем** (мысль автора): решения советника зависели от характера лидера, но не от расы — Дарлок-
шпион и Булрати-воин с одинаковым характером играли одинаково, отличие было бы «только в скине».
Раса должна *немного* влиять на решения: не жёсткий сценарий, а склонности, которые сдвигают пороги
уже существующих правил. Два независимых измерения — раса (что народ умеет) и характер лидера (как он
этим пользуется) — дают разнообразие: агрессивный Psilon и миролюбивый Mrrshan ведут себя по-разному.

**Склонности расы** (из `s_player::traits[]`, каждая от −2 до +2; флаг `advisor rules_race`):

| Склонность | Из каких черт | Что сдвигает |
|---|---|---|
| **Война** | +атака кораблей, +наземный бой, полководцы, телепатия; −слабый наземный бой, −фантастические торговцы; отталкивающая раса без друзей полагается на силу (+1) | «слабый сосед» для 405 и 406 — до 2/3 нашей силы (воинственные) или только до 1/3 (мирные) вместо половины; в коалицию сосед претендента вступает с 1/4 его силы (воинственные) или только с половиной (мирные) вместо трети; воинственные никогда не «ждут последними» |
| **Дипломатия** | харизма, фантастические торговцы; −2 отталкивающие | дипломаты (≥ 1) ищут союза со всеми, кого лидер-«Рим» обхаживает (ALLY, не FRIENDLY), — «пусть другие воюют, ты женись» (Габсбурги); отталкивающие (≤ −1) никого не обхаживают |

| **Скрытность** | малозаметные корабли, межпространственные | набеги на незащищённые колонии втрое ценнее (не вдвое) — «бей там, где врага нет» (Сунь-цзы) |

### 10.9 Сначала всё без LLM, затем большой стенд (решено с автором 22.11.2026)

**Почему** (вывод автора): дизайн механик сбалансирован как целое — мы предполагали, что всё будет
сделано сразу. Внедрение по частям неизбежно давало дисбалансы: вес флота без читающего его крюка
отнимал экспансию (10.4.3–10.4.4); коалиция без донесений не знала, есть ли помощь рядом (10.4.7);
подстава без контрразведки и компромата почти ничего не меняет (10.4.12–10.4.13). Поэтому сначала
строим все механики, кроме интеграции с LLM, и только потом настраиваем баланс на сотнях партий.

**Правила работы:**
- реализация идёт по готовому дизайну, с точки зрения программирования, а не геймдизайна: числа и
  правила берутся из [mechanics.md](mechanics.md) как есть; выводы о том, хорош ли план, — только
  после реализации всех частей и большого прогона партий (уточнение автора);
- каждая механика — за своим флагом, по умолчанию выключена до большого стенда (поведение для
  человека не меняется, пока флаги не включены);
- каждая часть проверяется **на правильность**, не на баланс: юнит-тесты, turn oracle 100/100 со
  значениями по умолчанию, `test_config_schema`, сейв с новой секцией загружается, и короткий
  прогон (8 партий по 200 ходов) показывает, что механика срабатывает, ничего не падает и она не
  «мёртвая». Выводов о балансе по частям не делаем;
- баланс — только на полном наборе.

## 11. Что уже сделали другие

Проектов с LLM-советником для AI-империй MOO1/MOO2/1oom, Stellaris, Endless Space не найдено
(ноябрь 2026). Для самой MOO2 есть два близких проекта:

- **openorion2** (Go, GPL-3.0, создан 30.10.2026, один автор) — реимплементация MOO2 1.40 один в
  один с оригиналом. Что есть для внешнего AI:
  - HTTP API `-control` с честным видом игрока (`/act {"view":{}}`) и приказами
    (`docs/control.md`); честный вид для любой империи — `playerView(p)`; обнаружение чужих
    кораблей «от имени» империи — временной подменой номера игрока (`detectedShips`);
  - `tools/agent` — LLM играет за человека через Ollama;
  - симулятор без экрана (~2 с на партию в 400 ходов) и обученная сеть-трансформер на 2,4 млн
    параметров: сначала подражание оригинальному AI (3000 партий), затем обучение с
    подкреплением (PPO, ~40 000 партий). Итог на 100 партиях: население вдвое больше, чем у
    оригинального AI, а место такое же и гибнет чаще — другой стиль, не большая сила.
    Сеть решает только исследования, очереди, работников и маршруты; дипломатию — нет.
  <https://github.com/openorion2/openorion2>
- **moo2-mcp** (Python, Linux) — MCP-сервер, который читает память оригинальной DOS-версии в
  DOSBox-X, чтобы Claude мог играть за человека; только чтение.
  <https://github.com/rapaul/moo2-mcp>

Ближайшие аналоги в других играх:

- **Vox Deorum** (Civilization V + Vox Populi) — та же схема «советник над встроенным AI»:
  LLM выбирает стратегию, характер, исследования и политику из закрытого меню (включая «без
  изменений»), тактика — у встроенного AI; работает асинхронно, пока ходят другие; без LLM
  управление возвращается встроенному AI. Итог: стиль игры другой, сила — как у встроенного
  AI. Проблемы: упрямство (34 и 13,9 смены стратегии на 100 ходов против 51,6 у встроенного
  AI), самообман, растущий контекст.
  <https://arxiv.org/html/2512.18564v2>,
  <https://forums.civfanatics.com/threads/beta-vox-deorum-0-6-3-play-civilization-with-llms-vp-5-1-3-compatible.701133/>
